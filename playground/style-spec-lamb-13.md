## 1. 三条底层定律
**A 一黑压全图**：只允许一种深色 `#4A3A26`（实测最暗 `#403323`，连灵动岛都是深棕）。两个半边——① **唯一**（不能有两种深色面）② **有色相**（锚点通道极差实测 36，肉眼看得出是棕）。
**B 高短波窄色带**：带色相像素（通道极差 >6）中 **73.1%** 落在 30°±10°；饱和度中位 14%、p99 52%、峰值 72%；明度中位 253/255，仅 5% 像素低于 L128。
**C 两套记号不混用**：物体记号 = 描边；容器记号 = 色差 + 大圆角 + 零描边。容器与底对比度 **1.26:1**，特性不是缺陷。

## 2. 色板
见速查卡。**签名「低饱和彩虹」**：`#D4B0A4`→`#E9C69F`→`#F3E2A4`→`#D9E4A5`→`#BEC3DC`，全图唯一允许多色并列处，每格饱和度 <30%。

## 3. 线条
主体 **3–4 px**（一级 1.0–1.2%）／道具 **2 px**（二级 0.6%），比例 ~1.6:1；全圆头圆角，**无压感、无收尖、无粗细渐变**；单色 `#403323`–`#664D39`。两级线宽本身就是层级手段。**断笔**：主体必须闭合，道具可留缺口。

## 4. 质感
平坦区高频残差实测 1.06 / 0.69 → **表面零纹理**。手作感 **100% 来自线条抖动与形状不规整，0% 来自材质**。允许的"软"元素只有三个且都是形状：外壳软投影、腮红气垫椭圆、放射光硬边扇形。

## 5. 分层
```
L0 画布底 #F2C993
L1 手机屏 #FEF2DF 圆角矩形 + 暖色软投影
L2 环境   地面带 #F3CF93 / 放射光 / 瓷砖缝 —— 低对比、不描边、不闭合
L3 容器   白卡 #FEFEF9、焦糖 dock #F4CF9E —— 大圆角、零描边、零投影
L4 主体   小羊（一级线 + 纯白填充），可跨压 L3、可出画
L5 贴纸   竖排标签 / 气泡 / 祝福词 / 星星 / Z / 五色条
L6 信息   时间、日期、昵称、图标文字 —— 唯一"规整"的一层
```
呼吸感来自 L4/L5 破坏 L3/L6 的网格；但 L5 每个贴纸自身必须是正的圆角矩形——**歪的是摆位角度，不是形状**。

## 6. 阴影
左缘亮度剖面 `L195 → L137`（16–18 px = 卡宽 5%），右缘对称。压暗 **30% 明度**、**色相不变**。**只有 L1 有投影**。

## 7. 尺度
见速查卡。留白实测：42.3% 奶油 + 9.2% 近白 → 一半以上必须是空的。

## 8. 角色
2 头身，头占全身高 55%。羊毛 = **一条连续的扇贝形花边轮廓（12–16 弧瓣）** + 纯白平涂，不画毛流不加体积，内侧 2–3 条短弧线。耳朵/角 = 两块 `#8A6242` 小圆叶斜插出羊毛，**第一识别符，任何姿态不可缺**。五官总面积 **< 脸的 15%**，全落在脸下 2/3；眼 = 2 点或 2 条下弯弧或**半睁的一条横线**，**不画眉毛**，嘴 = 1 点或 1 短弧，腮红 = 2 团无描边粉气垫 + 1 白高光点。四肢是无指节的圆头短棒。表情扩展靠外挂符号不重画五官。
> **识别三要点：扇贝轮廓 + 半睁眼 + 不画眉毛。**（本会话逐屏放大核对 6 屏，与另一条并行会话对同一角色的独立结论一致。）
**识别检验**：缩到 64 px 宽仍能认出"白团 + 两点棕耳 + 一条棕线"。

### 8.1 第二角色「小不点」（v13 新增——此前漏掉）
放大到 3 倍才看清：画面里有**两个角色**，不是一个。
| | 主角 懒懒 | 配角 小不点 |
|---|---|---|
| 身体 | 羊毛扇贝花边（12–16 瓣） | **光滑蛋形，无花边** |
| 头顶 | 两块 `#8A6242` 棕色角 | **两根细触角（短线 + 端点小圆）** |
| 脸 | 奶白，五官 <15% | 更简：两点黑豆眼 + 一个红嘴点 + 两团腮红 |
| 描边 | 一级线 | 一级线（同宽，但更短更疏） |
| 出场频次 | 每屏 1 次 | 每屏 0–2 次，**只出现在图标位与小组件里** |

**它承担的是整套语言的叙事核心**：「陪伴懒懒 001 天啦」——陪伴的对象就是它。它出现在支付宝图标（抱蓝色拼图块）、微信图标（顶绿色气泡雨）、以及"今日剩余 50%"玻璃罩 widget 的**顶上趴着**（罩内一朵花）。
> **可推广的规律**：这类"养成/陪伴"叙事必须有**一个比主角更弱的次级角色**，否则主角是在自言自语。次级角色的做法不是缩小主角，而是**减一层特征**（去掉花边、去掉角、只留圆 + 两点 + 腮红）——**同一套线宽与色板，少一半信息量**。
> **加进 BOM**：配角 1 个 + 配角动作 4–6 个（抱东西 / 顶东西 / 趴着 / 睡着）。

## 9. 排版
字阶 7.0 / ~6 / 5.5 / 4.0 / 3.4（屏宽 %），相邻比 ≈1.3–1.4，下限 3.4%。中文圆头手写黑体，字距 0.15–0.25 em。昵称 = 描边泡泡字（奶油字面 + 棕描边 + 逐字随机旋转 ±8°）。层级只用两档棕 + 字号；**没有白色文字**（定律 A 的直接后果）。对比度实测：正文 9.86:1 / 次级 4.06:1 / 装饰珊瑚 2.98:1。

## 10. 构图母题
① 顶部信息带三段式 ② 一条 dock（图标靠 ≥20 px 空隙分隔，**不靠格子、不靠光晕**，实测图标间底色恒 L202.3±0.2）③ 一个主角动作 ④ 竖排"星期"贴纸 ⑤ 五色小条 ⑥ 装饰外挂 ⑦ 破框（第 5/6 屏用双描边弧线斜切界面当分格）⑧ 拟物小零件（书签飘带、和纸胶带、便签、虚线）。

### 10.1 两条文字母题（v13 新增）
- **关键词上强调色，其余不上**：`距离 生日 还有 365 天` —— 只有"生日"是珊瑚红，其余全是 `--ink`。这是装饰色唯一合法的正文用法：**它替代下划线/加粗，做句中焦点，不做整句上色**。
- **数字上胶囊底**：`365` 坐在一个 `#F7DCAE` 的圆角胶囊里（胶囊圆角 ≈ 字高的一半），数字本身仍是 `--ink`。**强调靠垫一块浅色，不靠把字变粗或变红**。
> 这两条合起来解决了"强调色对比度只有 2.98:1，凭什么让它进正文"的矛盾：**句中焦点 + 胶囊垫底**，读者靠形状与颜色差识别，不靠该字的对比度达标。

## 12. 失败模式表（按致命度）
**S 级**：黑/冷灰描边 → 涂色本 ｜ 饱和度 >70% → 外卖大促 ｜ 出现第二种深色面 → 画面突然变重 ｜ 容器加描边 → 儿童 App UI ｜ 线有压感收尖 → 像插画不像界面
**A 级**：加纸纹噪点 → 手账模板生成器 ｜ 渐变填充/内外发光 → AI 感 ｜ 投影用黑灰 → 灰脏发闷 ｜ 给羊加体积高光 → Q 版 3D ｜ 羊毛瓣 >20 → 认不出是羊 ｜ 五官 >15% → 变成表情包
**B 级**：装饰 >5 个 → 看不出是界面 ｜ 全对齐无破框 → 规整但没手作感 ｜ 彩色描边 → 印刷错版 ｜ 字号 <3.4% → 糊 ｜ 缺 L5 → 干净但空洞 ｜ 深色模式翻成深蓝 → 全崩

## 14. 产品层
### 14.1 它在卖什么
三处文案（陪伴 001 天 / 距生日 365 天 / 已走 09421）说明它卖的是**把计数变成仪式**；愿意用 1.26:1 容器对比度、2.98:1 装饰文字对比度换情绪——**在壁纸这个载体上可用性可以牺牲，因为没人真的点它**。
### 14.2 生产节奏
一套 5–8 张，同一角色不同动作 + 同一 dock 图标反复复用（本图 6 张里"吃饭/睡觉/玩耍/洗澡"重复 4 次）。**复用是必需品不是偷懒**。
### 14.3 双轨制（已复算）
容器色差 1.26 →容器色差 1.26 → 产品轨想要 ≥3:1，但 `#E0B472` 实测只有 **1.73:1**，真到 3:1 要压到 `#AA8451`（3.10）——**那已是深色面，撞定律 A**。次级文字 `#7A6349` = **5.12:1** ✓。深色模式：线 `#F2C993`/底 `#3A2E22` = **8.50:1** ✓、正文 **11.91:1** ✓、卡/底 **1.21:1** ← 同样的容器问题。最小字号 ≥4% + 12 px；点击目标 ≥44 px 且**不加描边**，用缩放 0.96 表达按下（默认建议值，未实测）。
### 14.4 三条出路（可复制 CSS）
```css
/* ① 抬升（推荐，同屏容器 ≤4 时）：容器绝不写 border，用暖棕软投影做层级 */
.p-lift{ background:#FEFEF9; border:none; border-radius:24px;
  box-shadow:0 2px 10px rgba(160,110,50,.18), 0 0 0 1px rgba(242,201,147,.35); }
/* ② 留白（最符合本语言，最考验排版）：不画边界，用间距分组 */
.p-gap{ display:flex; flex-direction:column; gap:24px; }   /* ≥24px 才成组 */
.p-gap--tight{ gap:12px; }
/* ③ 发丝线：只给必须被点的元素；实测叠在 #FEF2DF 上 ≈1.3:1，不承担可达性 */
.p-hairline{ border:1px solid rgba(74,58,38,.14); }
```
> 真正需要 ≥3:1 的场合（表单边框、错误态）必须放弃焦糖、直接用 `--ink` 描边——**那一刻它就不再是这套风格了，要接受**。
> **这套风格天生不适合重表单、重数据的产品界面**；它适合内容展示、情绪化引导、装饰性组件。§25 给了这条判断的量化证据。

## 15. 风格坐标
四条线交点：**三丽鸥系角色造型 × 小红书手账贴纸排版 × Lo-fi 治愈色板 × iOS 界面骨架**。

```
不要彩色描边，不要复杂背景，不要文字，不要水印
```
→ 门禁 `1S+2A+2B`；人眼看出 6 处偏离：羊毛是米色不是纯白且有内阴影 / 有 die-cut 白边 + 地面投影 / **4 个棕色突起**（应 2 个）/ 腮红是实心圆点 / 背景飘 8 个装饰圆点 / 描边中位 **#93603E**（规定 `#4A3A26`）。

**骨架 v2**：把"无体积"拆成 4 个否定词（阴影/渐变/明暗过渡/体积感），补 `no die-cut white border`、"不要地面投影"、"不要装饰圆点"、"总共只有两个棕色突起"、腮红改"柔焦椭圆"。
→ 门禁 `1S+2A+0B`，但 **R1 70.6（更差）、R4 13.9（更差）、R9 43.9（更差）**；描边中位漂到 **#A76634**，描边占面从 2.0% 涨到 **6.9%（3.4 倍）**。

### 17.1 【实测结论】提示词管得住"不要什么"，管不住"要多少"
| 约束 | 靠提示词可行？ | 证据 |
|---|---|---|
| 表面零纹理 | **可行** | R6 两轮都 0.27–0.33，一句"无纹理无噪点无纸纹"就够 |
| 色相族 | **可行** | R2 两轮 87.0 / 88.3，高于参考图的 73.1 |
| 无中性纯黑 | **可行** | R5 两轮通过（但"过彩"，见下） |
| 纯白平涂、无体积 | **可行**，但要把"无体积"**拆成 4 个否定词** | v1 ✗ → v2 ✓ |
| 无 die-cut 白边、无地面投影 | **可行**，但必须写英文 `no die-cut white border`（中文"不要白边"没用） | v1 ✗ → v2 ✓ |
| 背景无装饰元素 / 腮红是柔焦椭圆 | **可行** | v1 ✗ → v2 ✓ |
| **锚点精确色值** | **不可行** | 写了 `#4A3A26`，v1 给 `#93603E`、v2 给 `#A76634`，**越约束越偏** |
| **两级线宽** | **不可行** | 两轮都只有一档（两级比 1.09–1.20）；"uniform"反而把单档锁死了 |
| **线宽绝对值 / 暗部面积** | **不可行** | "1% 画面宽"被理解成"粗线"，写更严反而粗 3.4 倍 |
| **角的数量（2 个）** | **不可行** | 明写"总共只有两个"，两轮都给 4 个 |
| **五官占脸 <15%** | **不可行** | 两轮都偏大 |

### 17.2 因此 AI 管线的正确分工
```
提示词负责：画法（扁平/平涂/无体积）、材质（无纹理）、画面里不许出现的东西
人工负责：锚点色值、两级线宽、主体占幅、角的数量、五官面积
```
**三步必做清洗**（不是建议）：① **色板吸附**到 §2 的 16 色——实测 v2 描边 `#A76634` 与 `#4A3A26` 差 ΔRGB≈(93,44,14)，不吸附必违反定律 A/B；② **线宽归一**到一级 1.1% / 二级 0.6%；③ **主体缩到画面 55–70%**——这条直接决定 R4 能不能过。
**出图后立刻跑 `--track=wallpaper`**；S 级不为 0 就回人工，**不要指望再抽一次卡能过——量化约束不是概率问题，是模型能力边界**。
**分层来源**：L0–L3 纯手工/代码（要精确 hex 与零描边）· L4 AI + 三步清洗 · L5 AI 小图或现成矢量零件 · L6 **必须手工排**（AI 出中文必错）。
> 附注：测试图右下角「Qoder AI 生成」是工具水印，不是风格问题，但会污染 R7（v1 的 51.0 有一半来自它）。跑门禁前裁掉。

### 19.2 六轮修门禁的记录（这些改动本身比结论有用）
1. **R9 聚类 bug**：1 px 抗锯齿毛边被计入分布，"两级比"算出 0.50。剔除后与 §3 对上。
2. **R2 判据换掉**：原用 HSV `S>12` 定义"有色像素"，把**极淡的粉底/奶油底判成无色**，分母只剩强调色 → 大面积浅色主题必被判死。改用**通道极差 >6** 后，粉色主题 43.7 → **92.2**，参考图 78.0 → 73.1，阈值随之 75 → **70**（73.1 是地板）。

### 19.3 可读性门禁 `contrast_audit.js`
CDP 驱动 headless Chrome，遍历作用域内**所有含直接文本的元素**，取 `getComputedStyle().color` 与**沿祖先链找到的第一个不透明 background**，算 WCAG 对比度，按字号/字重选 3:1 或 4.5:1 判。**跳过 emoji-only 节点**（表情字形不吃 `color`，第一版没跳，12 条失败里 6 条是假阳性）。它能做位图门禁做不到的事：**指名道姓**——输出 `选择器 + 文字内容 + 字号 + fg/bg`。

### 19.4 取景协议
| 项 | 规定 | 为什么 |
|---|---|---|
| 取景单位 | **一个界面 = 一张图**，禁止整页/多屏并排/注释区 | v7 的 R2 假阴性 |
| 覆盖度 | **主题里每个屏都要跑** | v9→v10 的过拟合 |
| `--unit` | 传**一个界面的像素宽**；多联图必传 | 否则 % 按整图算，跨图不可比（§19.2-6） |
| 输出倍率 | 建议 `deviceScaleFactor=2`；R9 已按 unit 归一，倍率不再影响结论 | 修前会影响 R9 |
| `--hue` / `--track` | **按屏设，不按主题设** | 深浅两版主色相可能不同（§21.5） |
| `--band` | 壁纸轨 10–12；产品轨 18–25 | 产品必须有功能色 |

**任何新加的检查项必须同时跑 ①已知正确的正例（要绿）②同源扰动反例（要红）③异源风格样本（要红）**。只跑前两类测不出"它对别的风格也永远绿"——R7 死在第③步。

## 20. 角色权属与自有 IP 的资产化

**权属（已由作者本人确认，2026-10-13）**：图中角色**是用户自有版权的原创形象，不是《喜羊羊与灰太狼》的懒羊羊**。本规范此前基于造型相似性做出的「疑似他人 IP」推断**作废**——相似的原因是**同一套 Kawaii 语法规则收敛到了相近的解**（白团 + 扇贝边 + 两点角 + 小五官 + 爱睡人设），这恰恰反证 §1–§11 的定律是**可推导的通用语法**，而不是某个 IP 的私有特征。

| 用途 | 状态 | 建议 |
|---|---|---|
| 个人壁纸、学习拆解、内部提案 | 自由 | 作者自有 |
| 对外发布的运营图、商品、周边 | **可用** | 做**权属留痕**：分层源文件（Figma/PSD + 创建时间）、首次公开发布的平台时间戳、角色设定图（三视图 + 表情表）单独存档 |
| 商用产品皮肤 | **可用** | 见 §20.1 可扩展性、§20.2 授权条款 |

> **一条与权属无关、但值得知道的观察**：`design/` 下那份主题文件的名字里带着别人的角色名。**那是你自己写的东西**，但文件名会出现在版本库、截图、协作链接里，别人读到会先入为主以为在蹭那个 IP——**观感问题，不是法律问题**。改不改由你定；规范里所有「疑似侵权」的表述我已撤掉。
| 用途 | 风险 | 建议 |
|---|---|---|
| 个人壁纸、学习拆解、内部提案示意 | 低 | 可直接复刻 |
| 对外发布的运营图、商品、周边 | **高** | 先确认授权，或**只借语言、不借角色** |
| 商用产品皮肤 | **最高** | 见下 |

### 20.1 自有 IP 的可扩展性：用同一套语法造「同族角色」
既然角色是你的，真正的问题不是「能不能用」，而是「**能不能再造几个而不散架**」。判据 = §8 识别检验反过来用：**新角色缩到 64 px 后，别人认不出它是哪个已有 IP，但认得出它和懒懒是一家的。**

| 层 | 必须不变（「一家」的来源） | 可以换（「新角色」的来源） |
|---|---|---|
| 线条 | 等宽棕线、圆头圆角、无压感、**两级线宽** | — |
| 体积 | 纯平涂、无阴影、无高光 | 身体填充色（白 → 允许一个浅色） |
| 五官 | 总面积 <15%、落在脸下 2/3、**不画眉毛** | 眼形（点 / 下弯弧 / 半睁横线） |
| 轮廓母形 | 必须仍是**一条连续闭合花边** | 弧瓣数 12–16、瓣的深浅 |
| 识别符 | **必须恰好两个、跨姿态不消失** | 角 → 呆毛 / 领结 / 一片叶子 / 一撮翘毛 |
| 情绪 | 靠**外挂符号**表达，不改五官结构 | 符号集（汗滴 / Z / 怒气纹 / 墨镜） |
| 色板 | 定律 A/B 的两个**分布**照抄 | 具体 hex：改 `--hue` 整体平移 |

**同族的最小配置**：1 个主角 + 1 个「减一层特征」的配角（§8.1）+ 若干「只换识别符」的旁支。
> 掉出家族的反例：加体积、把五官画大、或给它**三个**角——任何一条都会散，即使颜色完全一样。

### 20.2 要对外授权或做衍生时，把两层分开登记
**语言层**（定律 A/B/C、两级线宽、零纹理、破框、留白预算）= **风格**，通常不受著作权保护。**角色层**（扇贝羊毛 + 两点棕角 + 半睁眼 + 黄项圈 + 名字）= **作品**，可授权、可转让、可注册为商标。
→ **授权时只写角色层，别把语言层放进独占条款**——否则你以后自己换题材都会被自己签的约卡住。

### 21.2 三条被坐实的冲突（源码级证据）
**① 容器全部描边（定律 C）** — grep 原文件：
```
21 ×  border:2px solid var(--line)      ← .tile .pcard .chip .hbtn .cart-row 等
 1 ×  border:2.5px solid var(--line)    ← .panel
 7 ×  border:2px solid var(--clay-deep)
 3 ×  border:3px solid var(--clay-deep) ← .app 外壳
 3 ×  border:2.5px solid var(--clay-deep)
```
这套主题**用描边表达容器**，且线宽 **2 / 2.5 / 3 三档**（小羊是两级）。最根本的分歧不是颜色，是**边界语言**。
**② 出现第二种深色面 + 白字（定律 A / §9）** — `--clay #BE4E67` 被当**大面积实底**用在 16:26 时间条、"换一道"按钮、底部激活 tab；该色块上采到 **918 个纯白像素** = 白字。这解释了 R4 = 12.89%：**深色不是线，是面**。
**③ 锚点不带色相（定律 A 第二半边）** — `--ink #2B2429` 极差 **7**、`--n-paper #241B21` 极差 7；小羊的 `#4A3A26` 极差 **36**。

### 21.3 六屏终态（分轨 + 补丁 ⑦ + `--unit` 之后）
| 屏 | 轨 | 终态 | 剩余问题 |
|---|---|---|---|
| l0 首页 | product | **0S + 0A + 0B** ✓ | — |
| l1 宵夜（深色） | dark | **1S + 1A + 2B** | R1 饱和 73.3（临界）、R9 |
| l2 | product | **0S + 0A + 0B** ✓ | — |
| l3 | product | **0S + 1A** | R4 暗部 11.19%（该屏仍有深色面） |
| l4 | product | **0S + 1B** | 只有已证伪的 R7 |
| l5 | product | **0S + 0A + 0B** ✓ | — |
| **可读性（89 节点）** | — | **6 条 = 改前基线，零回归** | 6 条均为改前既有 |
| 首页 `16:26` 对比度 | — | 4.9:1（改前） → **9.5:1**（改后） | — |

**六屏里 4 屏全绿、5 屏 0 个 S 级失败、1 屏（深色）剩一条临界。**
（v9 曾报"改完 0S+1A"、v10 曾报"R9 改不掉"——两处都被 §19.2-6 的单位修正推翻了。）

### 21.4 视觉上的实际变化
改前 → 改后：**深色块全部消失后，那只被夹子夹住的线稿小羊第一次成了画面的重心**。改前它在和 16:26 时间条、"换一道"按钮、底部 tab 争"谁最深"，争不过；改后画面里只剩它一个有描边的实体。
→ **定律 A 的"唯一深色"不是审美洁癖，是把视觉重心让给主体的机制。你留几块深色面，就分走几次注意力。**

### 21.5 深色模式：加彩要"同族加深"，不能"跨族搬家"
| 做法 | 令牌 | 暗部色展 | **R2 色相集中** | 判定 |
|---|---|---|---|---|
| 改前 | `--n-paper:#241B21` 等 | 12 | 36.7 ✗ | — |
| **错：跨族搬到棕色** | `#2A2118`/`#33291E`/`#4C4030`（色相 ≈30°） | 21 ✓ | **26.7 ✗ 更差** | 修好一条、修坏一条 |
| **对：同族加深加彩** | `#331B26`/`#3B2230`/`#54364A`（色相 ≈330°） | **25 ✓** | **71.3 ✓** | 两条同时达标 |

**为什么搬棕色会失败**：`--hue` 是按**浅色屏**设的 340°。把深色令牌推到 30°，等于让深色屏主色相跑到 300° 之外——**深浅两版裂成两个色带，主题不再是一个世界**。
> **可推广规律**：给深色模式"加彩"时，**保持色相不变，只拉大通道极差**——固定 `hue`、把 `min` 通道压得更低、`max` 通道略升，而不是换一个看起来"更暖"的颜色。

### 21.6 这不是"错"，是"选了另一条轨"——但要说清代价
现有主题**已经在往产品轨走**（`--clay` on `--paper` = **3.98:1**，比小羊装饰色 2.98:1 强），对真界面这是对的选择。
- **L4 插画层它已经学到了**（等宽棕线、留白身体、外挂星星 ✦、虚线分隔、鼠尾草绿头像环）。
- **破在 L3/L6**：深色实底 + 白字 + 三档描边容器。
- 本案例证明：**L3/L6 可以被收敛，代价 = 619 字节 CSS + 一次可读性返工 + 一次深色令牌返工。**
> **结论**：这套语言能被本项目吸收的是 **L2/L4/L5**；**L3/L6 能吸收，但必须先把深色面让出来**，而且**必须双门禁 + 六屏全量跑**。

### 21.7 token 级对照
| 定律 | 现有粉色主题 | 判定 |
|---|---|---|
| A | 深色唯一性成立；**色相不足**（极差 7 vs 36） | 半通过 → 补丁后浅色轨、深色轨均通过 |
| B | 中性面色相 334.0–338.2、饱和度最高仅 **12.0%**（小羊中性面 39.5%） | **中性面比小羊更收敛**，改前 R2 就有 96.6 |
| C | `--card` vs `--paper` = **1.10:1**，另加 `--line` 发丝线（`#DECBD4` = **1.31:1**） | **混合态**：色差比小羊还弱，却又加了描边 |

## 23. 为什么是羊，而不是猫或熊
| 这套语言的要求 | 羊恰好提供 | 猫 / 熊 / 兔 会怎样 |
|---|---|---|
| 主体必须**纯白平涂** | 羊毛本来就是白的 → 不上色也合理 | 猫/熊要上色就有面积色，直接撞定律 B |
| 轮廓必须是**一条连续花边** | 羊毛 = 天然的 12–16 瓣扇贝边 | 猫是尖耳 + 光滑轮廓，线不"松"，手作感少一半 |
| 需要**跨姿态不变的识别符** | 两点棕色角，任何动作都在 | 猫的尾巴会随姿态消失 |
| 五官必须 **<15% 面积** | 羊脸被羊毛挤到中心，天然小五官 | 猫脸留白多，五官自然放大 → 滑成表情包 |
| 人设要能承载"**陪伴 001 天**"式文案 | "懒"= 不用产出价值也被原谅，最适合养成叙事 | 猫的"高冷"削弱被照顾感 |
| 需要能挂**道具**而不违和 | 圆头短肢无指节，抱蛋糕/端奶茶都不别扭 | 写实比例动物挂道具会串风格 |

> **选 IP 的准入清单**：主体要能留白（浅色身体）、轮廓要能天然成花边、要有一个跨姿态的识别符、五官能被"挤小"、人设要能承载"陪伴/等待/养成"这类无产出叙事。**满足 4 条以上不费力；≤2 条你会一直和风格本身较劲。**

## 24. 这套语言的代价：一条量化事实
把 §1–§11 忠实实现成 `lamb-style-kit.html` 之后，跑可读性门禁：

| | 风格门禁 | 可读性门禁 |
|---|---|---|
| 起步套件（忠实复刻） | **0S + 0A + 0B 全绿** | **19 个文本节点里 11 个不达标** |

不达标的全是**这套风格本来就允许低对比的地方**：泡泡字昵称（1.2:1，奶油字面 + 棕描边——**描边才是可读性载体，`contrast_audit` 只看 `color` 属性，测不到描边**）、竖排"星期五"三字（1.86 / 2.27 / 2.9:1）、清单序号（同色）、`好运/有钱` 祝福词（2.98:1）。
→ **两个结论**：
1. **这套风格与 WCAG 正文标准结构性不兼容**，不是实现得不好。要用在产品里，就按 §14.4 分工：**L2/L4/L5 用它，L3/L6 让位**。
2. `contrast_audit.js` 有一个已知盲区：**它不认 `-webkit-text-stroke` / SVG `stroke`**。凡靠描边救可读性的字（泡泡字、贴纸描边字），它一律报假阳性。判读时先排除这一类。
