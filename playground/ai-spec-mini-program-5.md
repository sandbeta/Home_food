# 1. 三条定律

**冲突时按 A > B > C 取舍。**

### A ｜ 一黑压全图
全图只允许**一种**深色：`--ink #4A3A26`。它同时是描边、文字、投影的色相。
- 禁止纯黑 `#000`、深灰、深蓝、黑色遮罩层。
- 锚点必须**看得出是彩的**：`--ink` 的 R/G/B 通道极差实测 **36**。任何自定深色锚点，极差必须 **≥ 20**。
- 深色**默认只当线用，不当面用**。要当面用只有一条例外，见 §7.3。

### B ｜ 高短波窄色带
- 色相：主色相 ±10° 覆盖**带色相像素**（通道极差 > 6）的 **≥ 70%**。参考图实测 73.1%。
- 饱和度：中位 14%、p99 ≤ 55%（壁纸轨）/ ≤ 70%（产品轨）、峰值 ≤ 72%。
- 明度：中位 ≥ 94%；低于 L50 的像素 ≤ 6%（壁纸轨）/ ≤ 8%（产品轨）。
- **超过一半画面必须是空的**（实测：42.3% 奶油 + 9.2% 近白）。

### C ｜ 两套记号不混用
| | 谁 | 记号 |
|---|---|---|
| **物体** | 角色、道具、图标内的图案、贴纸上的字 | **有描边** |
| **容器** | 卡片、dock、色块底、输入框底 | **零描边**，只靠色差 + 圆角 |

容器与底对比度实测 **1.26:1**。**这是特性不是缺陷**——给容器加一圈 border，画面立刻从「贴纸拼贴」退化成「儿童 App UI」。

> **投影的唯一例外**见 §5.4：功能轨允许容器带**暖棕软投影**来替代描边表达层级。这不是自相矛盾，是 §7.3 双轨制的必然结果——但必须用**暖棕**，绝不用黑/灰。

# 2. 单位制（先算这个）

```
--u = 屏幕宽度 / 100
```
| 平台 | 写法 | 1u 实际值 |
|---|---|---|
| Web / React（本项目现状） | `--u: 1vw` | 375px 屏 = 3.75px；390px 屏 = 3.9px |
| 微信小程序 WXSS | `1u = 7.5rpx`（750rpx = 屏宽） | 恒等，无需换算 |
| 原生 iOS/Android | 屏宽等分 100 份 | — |

**小屏保护（约定）**：屏宽 < 360px 时最小字阶从 `3.4u` 提到 `4.0u`。理由：`3.4u` 在 353px 以下跌破 12px，部分安卓机型会把 <12px 的中文强制放大或糊掉。

```css
/* Tailwind v4 —— 本项目 src/index.css */
@theme {
  --u: 1vw;
  --radius-shell: calc(var(--u) * 5.5);
  --radius-card:  calc(var(--u) * 4);
  --text-t1: calc(var(--u) * 7.0);
  --text-t2: calc(var(--u) * 5.5);
  --text-t3: calc(var(--u) * 4.0);
  --text-t4: calc(var(--u) * 3.4);
}
```
```css
/* WXSS —— 若移植原生小程序 */
page { --u: 7.5rpx; }
.t1 { font-size: calc(var(--u) * 7.0); }     /* = 52.5rpx */
```

# 4. 尺度表（u = 屏宽/100）

| 元素 | 值 | 备注 |
|---|---|---|
| 单屏比例 | 100 × ≥203 | 参考图被六宫格切过；**内容多时用 min-height，不要裁掉 dock** |
| 外壳圆角 | 5.5 | 真机可回系统连续曲率 |

| dock 内图标 | 12–17 | 图标间**靠 ≥5u 空隙分隔**，不靠格子、不靠光晕（实测图标间底色恒 L202.3±0.2） |

# 5. 图层与组件配方

## 5.1 图层顺序（z 从低到高）
```
L0 画布底 → L1 手机屏(+唯一投影) → L2 环境(地面带/放射光) → L3 容器
→ L4 主体 → L5 贴纸 → L6 信息
```
L4/L5 **允许**压破 L3 边界；L6 永远最上且规整。L5 每个贴纸自身必须是正的圆角矩形——**歪的是摆位角度（3–8°），不是形状**。
> ⚠ 压破的边界**只能是图片与色块，不能是文字**。见 §11。

## 5.2 卡片 Card（L3）
```
background: container-white
border: none            ← 铁律（定律 C）
box-shadow: none        ← 装饰轨；功能轨见 §5.4
border-radius: 4u
padding: 2u–3.4u
```

## 5.3 dock / tabBar（L3）
```
background: container-caramel
border: none; box-shadow: none
border-radius: 5.5u
width: 90u; height: 24u
图标: 15u，描边 secondary(0.6u)，无填充底
标签: t3，color: ink，tracking 0.18em
选中: 该项加 accent-honey 底 + 圆角 4u（自绘 tabBar 才做得到）
```

## 5.4 主按钮（两种，按 §7.3 选）
```
① 抬升（默认，功能轨）
  background: container-white  或  container-caramel
  color: ink                          ← 不是白字
  border: none                        ← 仍守定律 C
  box-shadow: 0 1u 4u rgba(160,110,50,.18)   ← 用暖棕投影替代描边表达层级
  border-radius: pill
  padding: 2.4u 6u
  按下: scale(0.96)                   ← 不加发光、不改阴影

② 唯一深色面（每屏最多 1 个）
  background: ink
  color: card-bg                      ← 不是 #FFF
  border: none
  实测对比度 9.86:1，一次拿到 AA 且不引入第二种颜色
```

## 5.5 贴纸族（L5）
| 贴纸 | 配方 |
|---|---|
| 竖排标签 | `container-white` 圆角 2.2u，三字各上一色（sage / honey-brown / coral），`rotate(-4deg)` |
| 气泡 | `container-white` 圆角 3u + 三角尾巴指向说话者，`rotate(2deg)` |
| 数字胶囊 | `accent-honey` 圆角 = 字高/2，数字用 `ink` |
| 句中焦点 | 只有关键词用 `accent-coral`，其余 `ink`，**且字号必须 ≥ t2** |
| 飘浮祝福词 | `accent-coral`，**≥t2 字号**，贴边不占中轴 |
| 外挂符号 | 汗滴 sky / Z blush / 四角星 honey 描 ink |

## 5.6 角色（L4）
- **主角 懒懒**：2 头身，头占高 55%。羊毛 = **一条连续的 12–16 瓣扇贝花边**，纯白 `#FFFFFF` 平涂，**无体积、无毛流、无阴影**，内侧只放 2–3 条短弧线。两个 `ear-brown` 小圆叶斜插出羊毛（**恰好两个，任何姿态不可缺**）。五官 < 脸的 15%，落在下 2/3，**半睁眼、不画眉毛**。四肢是无指节的圆头短棒。
- **配角 小不点**：光滑蛋形，**无花边无角**，头顶**两根细触角**（短线 + 端点小圆），两点黑豆眼 + 一个红嘴点 + 两团腮红。只出现在图标位与小组件里，每屏 0–2 次。**它是「陪伴 001 天」的陪伴对象。**
- 描边：主角一级 1.1u；配角与道具二级 0.6u。**主体轮廓必须闭合，道具可以断笔。**
- 识别检验：缩到 64px 宽仍能认出「白团 + 两点棕角 + 一条棕线」。

### 扇贝花边的生成式（不必手描）
```python
# N 瓣闭合花边；N 取 12–16；arc_r 系数 1.18 让瓣微微外凸
import math
N, R = 14, 100.0
pts = [(R*math.cos(2*math.pi*i/N - math.pi/2), R*math.sin(2*math.pi*i/N - math.pi/2)) for i in range(N)]
arc_r = math.dist(pts[0], pts[1]) / 2 * 1.18
d = f"M {pts[0][0]:.1f} {pts[0][1]:.1f} "
for i in range(N):
    x, y = pts[(i+1) % N]
    d += f"A {arc_r:.1f} {arc_r:.1f} 0 0 1 {x:.1f} {y:.1f} "
d += "Z"      # → fill:#FFFFFF stroke:#4A3A26 stroke-width:1.1u stroke-linejoin:round
```
放射光同理：16 个硬边扇形，`i%2` 交替 `ray-light` / `ray-dark`，**不要用 conic-gradient**（那是渐变，违反 §4 零材质）。

## 5.7 页面骨架（点餐场景）
| 页面 | 主力层 | 角色出场 | 注意 |

## 5.8 素材接入（**本仓库既有约定，不要另起一套**）
本项目已有单源登记制，实现前先读 `extracted/src/theme/characters.js`，照它的规矩来：

| 规则 | 做法 |
|---|---|
| **路径不散落** | 所有角色素材在 `characters.js` 里登记成 `CHARACTER.xxx = { src, name }`，页面只引 `CHARACTER.xxx`，**不写字符串路径** |
| 两类版本 | 悬浮在卡面上的大图（主推位 / 空态 / 弹窗 / 页尾探头）→ 用 `opaque/` **实底贴纸版**；已坐在实心圆底容器里的小徽记 → 用**透明底**，避免"圆里套方"双重描边 |
| 目录 | `public/lazy-assets/`（透明底）与 `public/lazy-assets/opaque/`（实底），现有 13 个素材 |
| 路径拼接 | 一律走 `assetUrl()`（`src/lib/assetUrl.js`），子路径部署才不 404 |
| 抠图奶白边 | 透明底素材边缘在深色上会带极淡奶白边 → **深色场景必须用容器（圆底/卡片）托住**，别直接铺在 `night` 底上 |
| 新角色 | 先在 `characters.js` 登记再生成文件；**没登记 = 不存在** |

> 这条与定律 A 同源：奶白边本质是"描边外侧多了一圈不属于色板的浅色"，在浅色底上看不见、在深色底上就是把画面弄脏的那 1%。

# 6. 状态与动效

| 状态 | 规则 |
|---|---|
| 按下 | `scale(0.96)`，150ms，**不动画阴影、不加发光** |
| 禁用 | 前景 `ink` → `ink-soft` + `opacity .45`；**底不动** |
| 加载 | 三个 `ink` 圆点跳 2 个身位；或配角探头。**骨架屏禁止用灰**（中性灰违反定律 A）→ 用 `ground` |
| 空状态 | **配角出场**（不是主角），配一句口癖 |
| 错误 | `accent-coral` 做图标与关键词；输入框错误态是唯一允许 `ink` 实描边的场合（§7.3） |
| 选中 | `accent-rose` 下划线 1.8u，或 `accent-honey` 胶囊底 |

**动效总则（约定，服从项目既有动效权威）**
- 时长 ≤ 300ms；只允许 **位移 + 缩放 + 透明度**。
- **禁止动画 `box-shadow`**（会让"第二个深色面"的观感漂移）。
- bounce ≤ 0.2。
- 角色按压时**整体缩放**，不做局部挤压变形——局部变形需要体积，这套语言没有体积。
- 转场用「贴纸飘落 / 破框进入」，不用淡入淡出（淡入淡出是系统语言，不是贴纸语言）。

# 7. 真实内容会怎样撞坏这套语言（**必读，含实测曲线**）

## 7.1 菜品照片 —— 目标性冲突，且**没有豁免区**

**先纠正我自己犯过的两个错：**
- ~~"塞进真实菜品照后 R2 通常掉到 40–55%"~~ → **那是我编的估计值**。实测：裸照片 R2 = **80.5–95%**，色相集中度根本没崩。
- ~~"推荐套 `#F4CF9E` multiply 18–25%"~~ → **实测是反效果**。

**实测取舍曲线**（合成菜品照 + 白卡网格，`--track=product --hue=30 --unit=600`）：

| 配方 | R1 饱和 | R2 色相 | S 级 | 观感 |
|---|---|---|---|---|
| 裸照片，不处理 | 82.4 ✗ | 80.5 | **1** | 有食欲，但破色带 |
| `multiply #F4CF9E @22%` | 83.5 ✗ | 87.6 | **1** | 更黄，**饱和反而升** |
| `multiply #F4CF9E @35%` | 84.3 ✗ | 90.1 | **1** | 最差，糊成一片焦糖 |
| `saturate(0.88) sepia(0.06)` | 75.3 ✗ | 82.7 | **1** | 几乎无损 |
| `saturate(0.80) sepia(0.10)` | 70.6 ✗ | 84.5 | **1** | 差 0.6 就过 |
| **`saturate(0.72) sepia(0.16) brightness(1.03)`** | **65.5 ✓** | 85.1 | **0** | **轻微褪色，仍好吃** |
| `saturate(0.62) sepia(0.24)` | 58.4 ✓ | 86.3 | 0 | 明显褪色 |
| `saturate(0.42) sepia(0.34)` | 45.5 ✓ | 86.5 | 0 | **完全不好吃** |

**照片数量扫描（这条最关键）**
| 照片数 | 裸照片 R1 | 裸照片 S 级 | 加 .72/.16 后 R1 | 滤镜 S 级 |
|---|---|---|---|---|
| 1 张 | 80.8 | **1** | 59.6 | 0 |
| 2 张 | 83.1 | **1** | 66.3 | 0 |
| 4 张 | 83.5 | **1** | 65.9 | 0 |
| 6 张 | 83.1 | **1** | 65.5 | 0 |

**四条结论**
1. **`multiply` 暖色叠层是错的方向。** 它把色相集中度推高（80.5→90.1）却把饱和度也一起推高（82.4→84.3）——**一层饱和焦糖去 multiply 只会加深，不会降饱和**。别用。
2. **`filter: saturate() sepia()` 才是解**：`sepia` 把色相往暖推、`saturate` 直接压饱和，一次治两个指标。
3. **不存在"少放几张照片就能豁免"。** R1 是 **p99 分位数——面积不敏感**。1 张裸照片和 6 张裸照片一样都过不了（80.8 vs 83.1，只差 2.3 点，而阈值在 70）。
   → **规则因此极简：页面上所有照片一律套 `--photo-fx`，没有例外区。** 不要设计"照片豁免面积"这种东西，统计上它不存在。
4. **可用下限是 `saturate(0.72) sepia(0.16) brightness(1.03)`。** 再往深（.42/.34）门禁分数更好看，但**菜品照片的产品目标就是让菜看起来好吃**——压成灰褐泥等于为了绿字毁掉功能。
   > 这是「门禁是护栏不是目标函数」最典型的一次：**最优门禁解 ≠ 最优产品解**。拐点 .72 就是两者的交点，别越过它。

**推荐顺序**
1. **首选不用照片，用插画**：菜品画成 0.6u 二级线宽的贴纸图标，纯平涂 + 暖色板。这是这套语言的母语，且没有取舍问题。
2. 必须用实拍 → 一律 `filter: var(--photo-fx)` + 圆角 2.6u + 白卡纸衬底（mat 2u）。
3. 若商家要求照片保真（外卖平台常见硬要求）→ **那一块界面就不该套这套语言**。把它划成"照片区"，只保留圆角与留白节奏，色带规则对该区域豁免并在代码里注明。

**样本局限（诚实声明）**：测试用的是合成色块盘，偏暖（红/橙/黄为主），所以 R2 天然不难。**真实菜品里的大量绿叶菜、蓝色餐具、白色米饭会把 R2 压得更低**。落地前请用你自己的 3–5 张实拍复跑 §12.1 的命令。

**另一条实测噪声**：含照片的页面上 R9（线宽分布）不稳定——同一套 CSS，裸照片 62.5% 通过、深滤镜版 53.9% 不通过，只差 8.6 点而阈值卡在 55。**照片页的 R9 失败可以忽略，别为它改线宽。**

## 7.2 长中文菜名 / 规格
- 菜名 4–8 字用 t2；超过 8 字换行，**不省略号截断**（这套语言的气质是松弛，截断是效率工具的动作）。
- 规格（小份/大份/辣度）用 §5.5 数字胶囊语汇，不用下拉框。选中 = `accent-honey` 底 + `ink` 字。
- **留白是唯一分组手段**：组内 ≤3.5u，组间 ≥7u。不加分隔线；实在要分，用 `ink` 8% 虚线（手账语汇），一屏最多一条。

## 7.3 对比度冲突 —— 必须正面裁决
**实测事实**：忠实复刻这套风格，19 个文本节点里 **11 个过不了 WCAG**（泡泡字昵称 1.2:1、竖排标签 1.86:1、祝福词 2.98:1）。**这是风格的结构性代价，不是实现问题。**

**裁决：把界面拆成两个轨，物理分开**
| | 装饰轨（L2/L4/L5 + 展示型内容卡） | 功能轨（表单/价格/按钮/导航/错误态） |
|---|---|---|
| 定律 A | 严格 | **一条例外**：允许 `ink` 当填充，每屏 ≤1 个，文字用 `card-bg` 不用 `#FFF` |
| 定律 B | 严格（S p99 ≤55%） | 放宽（S p99 ≤70%） |
| 定律 C | 容器零描边零投影 | 容器零描边，**允许暖棕软投影**（§5.4 抬升） |
| 容器色差 | 1.26:1（特性） | ≥3:1，靠**抬升或留白**达成，**不靠把容器调深** |
| 次级文字 | `ink-soft` 4.06:1（只给装饰文字） | **`ink-a11y` ≥4.5:1**（实测 5.12:1） |
| `accent-coral` 承载文字 | 允许，但**字号必须 ≥ t2**（实测 t2 时 2.98:1 恰好达大字号 3:1 线；t3 以下不达标） | **禁止**，退为纯图形 |

> **为什么例外只给 `ink`**：`#4A3A26` 上放 `#FEF2DF` = **9.86:1**，一次拿到 AA 且**没有引入第二种颜色**。这是唯一能同时满足定律 A 和功能可达性的解。
> **为什么"≥3:1 不靠把容器调深"**：实测焦糖要达 3:1 必须压到 `#AA8451`（3.10:1）——那已经是深色面，撞定律 A。**层级靠投影和留白，不靠色差。**
> **小控件永不许拿 `ink` 当底**：加购钮、步进器、图标底这类**会重复出现**的元素，一旦用 `ink` 填充，一屏就会出现 30+ 个深色面，"每屏 ≤1 个"当场失效（实测踩过：菜单页 32 个 ink 加购钮）。它们一律用 `honey` / `caramel` 底 + `ink` 字。
> **`ink-soft` vs `ink-a11y` 怎么选**：问一句"这条信息读不到会不会出错？"——会（价格、天数、日期、提示）用 `ink-a11y`；不会（纯装饰的口号、氛围文字）才用 `ink-soft`。

## 7.4 深色模式（宵夜）
**反相层级，不反相色相。**
```yaml
night:
  page-bg: "#331B26"      # 沿你自己的品牌色相族加深，不是搬去棕色
  card-bg: "#3B2230"
  ink:     "#F2C993"      # 让原来的线变成最亮的东西
```
- 实测：线 `#F2C993` / 底 `#331B26` = **8.50:1**；正文 `#FEF2DF` = **11.91:1**。
- ⚠ 卡与底只有 **1.21:1** → 深色模式的容器边界**必须用投影或留白，不能靠色差**。
- ⚠ **加彩必须同族加深**：保持色相不变、只拉大通道极差。把深色令牌搬到别的色相族（粉紫 → 棕色）会让深浅两版裂成两个色带——实测 R2 从 36.7 **反跌到 26.7**。

## 7.5 小程序平台硬约束（约定，需按目标基础库实测）
| 约束 | 影响 | 对策 |
|---|---|---|
| `navigationBarTextStyle` 只接受 `black`/`white` | 奶油导航栏上无法用 `ink` 色标题 | 选 `black`；平台强制，走 §9 第 7 条 |
| `navigationBarBackgroundColor` 只接受实色 hex | 不能用 rgba/渐变 | 填 `#FEF2DF` |
| tabBar 图标要 PNG、约 81×81、≤40KB | 0.6u 描边图标在小尺寸易糊 | 导出时线宽放大到 ≥3px 等效 + 2px 透明边 |
| tabBar `selectedColor` 是纯色 | 无法表达「抬升」 | 选中用 `accent-honey` 胶囊底；**自绘 tabBar 可完全遵守 §5.3** |
| `<image>` 对 SVG 支持不稳定 | 扇贝羊毛是 SVG path | **角色资源必须导出 PNG/WebP** 或 canvas 绘制，别指望 SVG |
| 自定义中文字体需 `wx.loadFontFace` | 手写体全字库常 >1MB | 子集化后走 CDN **不进包**；必须有系统字体兜底；体积与降级观感**待实测** |
| 部分安卓机型 <12px 中文被放大/糊 | `3.4u` 小屏跌破 12px | §2 小屏保护 |
| `letter-spacing` 末字后留尾空 | CJK 松排右侧显空 | 容器加等量 `padding-left` 补偿 |
| `env(safe-area-inset-bottom)` | dock 被 iPhone 横条压住 | 底部内边距 = 3u + safe-area |
| 固定高度 + `overflow:hidden` | **本项目实测踩过：dock 和计数卡被整块裁掉，门禁仍全绿** | 用 `min-height`，不用 `height` |

# 8. AI 能做到什么、做不到什么（实测结论）

对参考图做过两轮 AI 生图实测：**否定式约束 100% 生效，量化约束 0% 生效。**

| 交给 AI（提示词可靠） | 必须后处理（提示词不可靠） |
|---|---|
| 无纹理 / 无噪点 / 无纸纹 | **锚点精确色值**：写了 `#4A3A26`，两轮分别给 `#93603E`、`#A76634`，**越约束越偏** |
| 无渐变 / 无体积 / 无阴影 / 无高光 | **两级线宽**：两轮都只出一档；"uniform" 反而把单档锁死 |
| 无 die-cut 白边、无地面投影（要写英文 `no die-cut white border`，中文没用） | **线宽绝对值**：「1% 画面宽」被理解成粗线，写更严反而粗 3.4 倍 |
| 背景无装饰元素 | **角的数量**：明写「总共只有两个」，两轮都给 4 个 |
| 色相族（把 hex 写进提示词即可） | **五官占脸 <15%**：两轮都偏大 |

**分工固定**
```
L0–L3  → 代码/矢量，纯手工。需要精确 hex 与零描边，AI 做不到
L4 主体 → AI 出图 + 人工三步清洗
L5 贴纸 → AI 出小图，或直接用现成矢量零件
L6 文字 → 必须代码排。AI 出中文必错
```
**AI 出图后三步必做清洗**：① 像素吸附到 §3 的 16 色；② 线宽归一到 1.1u / 0.6u；③ 主体缩到画面 55–70%。
**S 级门禁不过就回人工重出，不要指望再抽一次卡能过——量化约束不是概率问题，是模型能力边界。**

# 9. 规则没覆盖到时，按这个阶梯推

```
1. 回到 §1 三条定律，A > B > C。
2. 这个元素是「物体」还是「容器」？→ 决定有没有描边（定律 C）。
3. 它在 L0–L6 的哪一层？→ 决定能不能压破边界、有没有投影（§5.1）。
4. 它是装饰轨还是功能轨？→ 决定对比度要求（§7.3）。拿不准按功能轨（更安全）。
5. 这条信息读不到会不会出错？→ 会就用 ink-a11y，不会才用 ink-soft（§7.3 末）。
6. 需要新颜色？只允许在 §3 的 16 色里选。一个都没有 → 先怀疑需求本身，
   再考虑在主色相 ±10° 内插一个，并加进 token 表（不许散落使用）。
7. 需要新尺寸？只用 §4 表里的值 × 整数倍。不许出现表外奇数值。
8. 平台强制与本文冲突（§7.5）→ 服从平台，并在代码里留一行注释说明是被迫的。
9. 门禁绿但产品目标受损（如 §7.1 照片压到不好吃）→ 产品目标优先，
   并把这个豁免区写进文档。门禁是护栏，不是目标函数。
10. 以上都不能定 → 选「更空、更淡、更接近白色」的那个方案。
    这套语言失败的方向永远是「太满、太重、太彩」，不是「太空」。
```

# 10. 文案语气与数字呈现

这套语言的文案不是"UI 文案"，是**角色的口癖**。参考图里的全部语料：
`没事哒` / `你在偷吃吗？` / `哈~ 好舒呀~` / `今天吃什么嘞？` / `懒懒玩的很开心~` / `早点早起哦~` / `快乐至上！` / `今日好运 UP` / `美丽` / `有钱` / `好运`

## 10.1 语气规则
| 规则 | 说明 |
|---|---|
| 人称 | 对角色说话用第二人称，角色回应用它自己的口吻。**不用"您"，不用"用户"** |
| 句尾 | 允许 `~`、`哒`、`哦`、`嘞`、`呀`；**每屏 ≤3 处**，多了就腻 |
| 长度 | 单条 ≤12 字。口癖不是说明文 |
| 禁止 | 感叹号连用、emoji、网络热梗、"亲"、"哦~"式客服腔 |
| 禁止 AI 腔 | 不用"精心打造""极致体验""一站式""赋能"；不用斜杠串（"好吃/好看/好玩"）；不用程度副词堆叠（"非常""极其"） |
| 空状态 | 让**配角**说话，不是系统说话。例：`锅是空的诶` |
| 错误 | 角色担责而不是怪用户。例：`懒懒记错了，再来一次` |

## 10.2 泡泡字是**角色名专用**
描边泡泡字（奶油字面 + `ink` 描边 + 逐字歪）只用于**角色的名字**。页面标题、菜名、分类名一律 `t2/t3` 的普通 `ink`。
> 实测踩过两次：把"找菜""锅巴"和菜名塞进昵称槽，结果整页标题都在冒充角色名，视觉重心全乱。**判据：这一屏上唯一被"描边加粗"的那几个字，是不是角色的名字？不是就是错了。**

## 10.3 数字呈现（这套语言的签名）
| 规则 | 值 |
|---|---|
| 字体 | 圆角粗体显示字 + `font-variant-numeric: tabular-nums`（**必须**，否则天数会跳位） |
| 补零 | **天数补零到 3 位**：`001`、`014`。计数是仪式不是数据 |
| 单位 | 单位字用 `ink-a11y` + t3，数字用 `ink` + t1/t2，**不同字号不同色** |
| 强调 | 数字要突出时套 `accent-honey` 胶囊（圆角 = 字高/2），**不许把数字变红变粗** |
| 价格 | `¥12` 全用 `ink`。**价格不是强调色该干的事**，句中焦点才是 |
| 关键词 | 一句里只允许 1 个 `accent-coral` 词，且字号 ≥t2 |

# 11. 布局铁律（**三次"全绿但坏图"换来的**）

做工作样例时，风格门禁连续三次给出 `0S+0A+0B` 全绿，而画面分别是坏的：
1. 主角用 `absolute` 盖住了整张菜品卡的照片和菜名。
2. 标题被塞进 flex 行里和主角抢宽度，CJK 被挤成**一字一行的竖排**。
3. 手机壳用固定 `height` + `overflow:hidden`，**dock 和计数卡被整块裁掉**。

**门禁看不见这三件事中的任何一件。** 因此：

| # | 铁律 | 为什么 |
|---|---|---|
| 11.1 | **破框只允许压在图片、色块、地面带上，绝不允许压在文字上** | 压文字 = 信息丢失，而颜色全合规 |
| 11.2 | **CJK 标题不要放进 `flex` 和固定宽度元素抢空间**；要横排就给块级容器 + 显式 `line-height` | CJK 没有词边界，宽度不够就一字一行 |
| 11.3 | **屏幕容器用 `min-height` 不用 `height`**；dock 用 `margin-top:auto` 且必须可见 | 裁掉的内容在截图里"不存在"，门禁测不到 |
| 11.4 | **绝对定位的装饰层 z-index 必须低于一切 L6 文字** | L5 贴纸压住 L6 = 读不到 |
| 11.5 | **截图之后先自己看一遍整屏**，再跑门禁。顺序反了就会交付坏图 | 全绿是必要条件，不是充分条件 |
| 11.6 | **`--unit` 必须传「截图里一个界面的像素宽」**，不是 CSS 宽。用 `shot_el.js` 它会直接把正确的数打给你 | 2x 截图传了 CSS 宽会让所有线宽翻倍 → R9 假失败（实测 48.3% vs 58.4%） |
| 11.7 | **触摸区下限必须写 `max(44px, Nu)`，不能只写 `Nu`** | `u` 随屏缩、44px 不缩。实测 320px 下所有 `u` 表达的按钮跌到 35–42px，全线不达标；改成 `max()` 后 12/12 通过 |
| 11.8 | **跑在主题化应用里的插画/角色 SVG，颜色必须走 `currentColor` + CSS 变量，不许内联 hex** | 实测：`art.js` 内联 `#4A3A26` 后，宵夜深色页的 dock 图标变成"深棕压在深紫上"，**完全看不见**。⚠ 这与"交付可编辑 SVG 要内联 fill/stroke"是**相反**的要求——按用途选：给 Figma/AI 编辑的导出件用内联；跑在应用里的用 `currentColor` |
| 11.9 | **R9 在大面积曲线页会系统性偏低，判读看「主档 + 两级比」不看百分比** | 圆的水平弦长随倾角变化，等宽描边在浅角处被量成更宽的 run。实测同一套线宽：详情页（一张 1:1 大插画）43.9%，列表页（多张小图）77.0%，而主档与两级比完全一致 |

# 12. 自检闭环（交付前逐条打勾）

## 12.1 命令链（可整段复制）
```bash
cd playground
node   shot_el.js ".phone" 0 out.png your-page.html
#      ↑ 它会打印：saved out.png | 截图实际像素宽 680 → 下一步请传 --unit=680
python style_lint.py out.png --track=product --hue=30 --unit=<它刚打印的那个数>
node   contrast_audit.js your-page.html ".phone"
```
**`--unit` 是最容易填错的参数**（§11.6）：要传**截图像素宽**（= CSS 宽 × 截图倍率），不是 CSS 宽。填小了门禁会**对称告警**并给出原因，不会让你对着一个假失败瞎改线宽。

**期望**：风格门禁 **S 级 0 失败**。承重项 R5 纯黑 / R6 纹理 / R1 饱和 / R2 色相集中。
**可忽略**：R3、R7、R8（已判定无判别力）；照片页的 R9（§7.1 末）。
**参照物**：`lamb-home-example.html` → 风格 **0S+0A+0B**；可读性 28 节点 **7 条不达标，全部落在装饰轨且逐条可解释**。

- [ ] dock 和底部内容**没被裁掉**

## 12.3 验证工具链的三条坑（都踩过）
| 坑 | 症状 | 对策 |
|---|---|---|
| **被缓存的是 `index.html`**（内联 `<script type=module>` 在里面） | 改了 `pages.js` 但截图还是旧版，`Network.setCacheDisabled` 也压不住 | cache-buster 必须加在**文档 URL** 上，且**插在 `#` 之前**——`index.html#night?v=1` 会让 `?v=` 变成 hash 的一部分，路由直接不匹配 |
| **`captureBeyondViewport` 对超高元素不可靠** | 7390px 的菜单页顶部拍成一片页面底色，看起来像"页面空白" | 先把视口 `height` 撑到内容全高，重新量 bbox，再正常裁剪 |
| **把工具输出重定向到 `/dev/null`** | 脚本抛了 `ReferenceError` 没人看见，`cp` 复制的是**上一轮的旧图**，门禁拿着旧图报绿 | 验收循环里**不许吞输出**。每轮至少打印文件名与尺寸，尺寸没变就是没重拍 |
