## [2026-09-28 02:30] US-003 接入停靠药丸与吸顶栏（含三个根因修复）

**做了什么**
- 停靠药丸与吸顶栏各挂一块 `<LiquidGlass>`，几何由 `useGlassRect` 每帧 `rectOf()` 读，>0.5px 才 setState（静止零重渲染）。原 `.glass-op` / `.glass-op--sticky` 保留作首帧与降级态。
- 对齐实测（headless Chrome + CDP，390×844，`measure_glass_gap.mjs`，同一矩形截两次：有 GL / 藏掉 GL）：
  - 白天 /menu y=0：webgl 0.6199 / css 0.6175 / **diff +0.0024**，逐像素不同 3.4%（最大通道差 13）
  - 白天 /menu y=900：**diff +0.0057**，逐像素不同 **21.7%** → 折射带真的在位移采样，不是均匀蒙版
  - 夜宵 /menu y=0：diff 0.0000，逐像素不同 0% —— 夜宵药丸身后是**纯色暗底**，任何位移采到的都是同一个颜色。这是「玻璃在平底上退化成描边框」那条定律，不是 bug。
  - **判据教训**：只看亮度差会把「GL 根本没画」误判成完美对齐（夜宵就是 0.0000）。必须同时报「不同像素占比」。

**三个真实根因（都不是 tint，tint 保持 22% 没动）**
1. **纹理漏了「洗白遮罩层」**，采到的是没洗过的原片：药丸处纹理亮度 0.175 vs 真页面 0.618。
   修：新增 `parseLinearGradient` + `paintBackgroundImages`（多层背景按 CSS「排前在上」倒序画）、`data-bd-layer` 采集钩子（App 纸底壳、FullBleedHero 晨光叠层）、底噪层补画 `--vignette`（伪元素选不到，直接读令牌）、图片按元素自身 computed `filter` 画（Hero 的 `blur(14px) brightness()`）。→ 亮度差 −0.4428 收到 −0.2056。
2. **`color-mix()` 被 Chrome 序列化成 `color(srgb 1 0.976471 0.988235 / 0.22)`，通道是 0–1 浮点**，而旧 `resolveColor` 按 `rgba()` 的 0–255 抓数字 → 白天的白纱变成 1/255 的**黑纱**（col×0.78），上缘高光画成黑环。夜宵因为写成字面 `rgba()` 反而没中招 —— 所以只有白天暗。
   修：新建 `src/lib/cssColor.js`，两级解析（探针元素展开 var()/color-mix() → 1×1 canvas `getImageData` 归一成 0–255），`backdropTexture` 与 `LiquidGlass` 共用一份。→ 亮度差 −0.2056 收到 +0.0024。
3. **shader 输出 `vec4(col * inside, alpha)`，而 context 是 `premultipliedAlpha:false`** → 合成器再乘一次 alpha，抗锯齿带上等于乘两遍，玻璃外圈描出一圈灰环，恰好把只有 1–2px 宽的折射识别带涂掉。修：改 `vec4(col, alpha)`。

**顺手修掉的层叠错误**：吸顶栏的 `--scrim-top` 渐变原先写在宿主 `style.background` 上，被负 z 的玻璃层整个盖掉（CSS 绘制顺序：宿主背景 → 负 z 子层 → 内容），浅色页顶糊成一条深灰带。搬成玻璃之后的 `absolute inset-0` 兄弟节点，WebGL 缺席时渐变照样在。

**给后续迭代的经验**

- git-bash 会把 `'#/menu'` 这类带斜杠参数当路径转换（实测到进程里变成 `C:/Program Files/Git/menu`）→ 脚本只收路由名，`#/` 在代码里补。

  之前报的「夜宵 diff 0.0000、逐像素 0 差异」量的是别人的像素。现在会直接判「无效」。

**四处真因**
1. **CSS 与 shader 的模糊半径不同源**。`.glass-op--sticky` / `--scrim` 的 backdrop-filter
   写死 `blur(14px)`，而 shader 的 panel 档读 `--glass-blur-panel`（9px）。
   吸顶栏压在照片上时亮度差 0.087 —— 全部来自这一处。改读同一个令牌后：
   light sticky diff 0.0452 → **0.0024**（纯玻璃 0.0871 → **0.0146**）。
2. **filter 的色彩空间没对齐**。`color-interpolation-filters` 的初始值是 **linearRGB**，
   所以 CSS 的 saturate/brightness 在线性光里算，而 shader 的 sat3() 在 sRGB 编码值上算。
   给四个操作层表面统一写 `color-interpolation-filters: sRGB`（也让门禁的 sRGB 建模成立）。
3. **纹理漏了 `background-image: url()` 的内容**。/home 底部菜品卡的主图是背景图不是 `<img>`，
   纹理里那排卡是空的粉底 → 同点真页面 0.742、纹理 0.831，GL 比 CSS 亮 0.09。
   补 `paintUrlLayer`（按 `background-size` 的 cover/contain/auto 画，url 走 bgCache，
   图 onload 里 markDirty，所以不需要再给脏判定加一条热路径扫描）。
4. 顺手修掉 `detach()` 里 `removeEventListener` 传新函数引用（永远解绑失败）+
   MutationObserver/img 监听从不释放。

要不要把文字也采进纹理，是一个**产品取舍**，不是纯技术活，需要用户点头：
- 做法：遍历有直接文本子节点的元素，用 `Range.getClientRects()` 拿每行的行框，
  按元素自己的 computed `font` / `color` 在 canvas 上 `fillText`。
- 代价：每帧多几十次 getComputedStyle + 文本测量（滚动热路径）；而且字形被折射
  「弯」出来时会糊成一团团灰，观感可能比「不采文字」更差 —— iOS 确实弯文字，
  但它的玻璃背后是整帧合成缓冲，我们没有。
- 备选：把 GL 层的不透明度从 0.96 降到「让 CSS 那层透出一部分」，用混合掩盖缺字。
  便宜，但等于承认两层都不完整。

**其它要记住的**
- 主题别再用 `?theme=` 设：它会打开「调试模式：主题被 URL 锁定」横幅，横幅正好压在
  吸顶栏中心上，把命中测试和像素一起污染。改用 localStorage，但**手动值只在时段身份戳
  与当前时段一致时才生效**，戳格式是 `年-月(0基+1)-日-自动档`（最后一截是自动档不是手动值）；
  随便写个 ISO 串会让覆盖静默失效 —— 实测有四组数据其实是 night 却当成 light 在分析。
- 凌晨 0—5 点跑验证，全站默认就是 night。想看 light 必须显式设，别信默认值。

### 退回去的（以及为什么）

2. **主题开关（41px 圆钮）不接 WebGL 层**，保留 `.glass-op .glass-op--ctl`。

每帧多几十次 getComputedStyle（滚动热路径），以及字形被折射弯出来会糊成灰团 —— 后者是
观感取舍，不是纯技术活。**所以没有为了让门禁变绿而硬上**，等所有者定。
